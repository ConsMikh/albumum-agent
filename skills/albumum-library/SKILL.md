# Библиотека, каталоги и корзина Albumum

Общие правила, подтверждение, коды выхода и ключ — в скилле `albumum`. Здесь — файлы автора: из них
собираются альбомы.

## Загрузка папки

```sh
albumum folders list                                 # каталоги библиотеки и число файлов
albumum folders create "Поход на Эльбрус"            # новый каталог; номер — в ответе
albumum library upload ~/Фото/Эльбрус --folder 12    # файлы и папки (рекурсивно), скрытые — мимо
```

Утилита сама считает хэш, спрашивает систему пачками и загружает только новые. Отчет:

- `uploaded` — загружены (`id`, `kind`, `status`: `processing` — показ-версии еще готовятся, `ready` —
  готов, `failed` — не обработался);
- `skipped` — уже в библиотеке (`duplicate`) или в корзине (`trashed`), с `media_id`; второй копии нет;
- `rejected` — отклонены с `code` и `reason` (не тот формат, больше предела, файл не читается);
  `network_error` с `hint` — повтори загрузку;
- `ignored` — не медиа (`.txt`, `.AAE`, `.xmp` рядом со снимками, `._*`): утилита их не отправляет, на код
  выхода они не влияют; если в папке нет ни одного медиафайла — код 1;
- `aborted` и `not_attempted` — загрузка прервана (ключ, темп, контракт, сбой предпроверки): код выхода —
  код прервавшей ошибки, `not_attempted` — файлы, до которых не дошло.

**Сразу после загрузки** часть файлов — `processing`: такие не ставятся на листы («еще не готов» в
`invalid_document`), у них нет показ-версий для `library image` и изображения листа. Прежде чем
верстать и рисовать, дождись `ready`: `albumum library list --folder 12 --all` (поле `status` у каждого
файла) или `albumum library get 501` для одного; есть `processing` — подожди полминуты и проверь снова.
`failed` — назови автору файл, на листы его не ставь.

**Дата съемки.** Нет даты в файле (EXIF) — система ставит момент загрузки (`taken_at_known: false` в
карточке). Такую дату не выдавай за дату съемки и не выдумывай свою: скажи автору, каким файлам даты
не хватает, и предложи задать ее (`albumum library taken-at`, ниже) — до подписей с датой на листах.

Код 6 («частично») — загрузка прошла, кроме перечисленных в `rejected`: разбери каждый (`code`,
`reason`, `hint`); `network_error` — повтори ту же команду. Код 1 без `aborted` — не прошел ни один
файл. Оборвалось или прервано —
повтори ту же команду: загруженное пропустится по хэшу, дублей не будет. Человеку — итог одной строкой
и перечень отклоненных с причинами. Файл из `trashed` вернуть — `albumum trash restore media:ID`.

## Собственные украшения

Свои рамки, надписи-картинки и стикеры — файлы библиотеки вида `decoration`: PNG или WebP с прозрачным
фоном. Видны во всех альбомах автора («Мои украшения» в редакторе), другим авторам — нет. Зачем и как
их делать и ставить в места — скилл `albumum-design`.

```sh
albumum library upload --decoration ~/albumum-work/frame-p3.png ~/albumum-work/title.webp --wait
albumum library list --kind decoration                 # свои украшения; --kind all — все виды
albumum library get 812                                # карточка: window, transparent
```

- Без `--decoration` PNG с прозрачностью загружается как фото: вид файла задаешь ты.
- Файлы не PNG/WebP утилита с `--decoration` не отправляет — они в `skipped` с причиной. Система
  отклоняет `not_decoration_format` (не PNG/WebP или анимированная картинка — сохрани один кадр) и
  `not_transparent` («у картинки нет прозрачного фона») — исправь файл и загрузи снова украшением, а не фото. Картинка, прозрачная меньше чем на 1 %
  площади, после обработки — `failed` («картинка целиком непрозрачная»): такую на листы не ставь,
  удали (`albumum library trash 812`) и сделай новую.
- Вывод: `uploaded` — `{file, id, kind, status, window}`, `skipped` — пропущены (не тот формат, дубль:
  «уже есть в библиотеке как фото» — тот же файл лежит фото), `failed` — не прошли обработку.
  `--wait` ждет обработки до 120 с; не дождались — `pending` и код 6, проверь позже `library get`.
- `window` — прозрачное окно `[левый, верхний, правый, нижний]` в долях картинки, если оно внутри
  картинки и каждая сторона не меньше четверти: тогда украшение годится рамкой на фото (`frame_media`,
  скилл `albumum-layout`). `null` — ставится только украшением.
- Пределы — как у фото (`limits.decoration_max_mb` в `albumum contract`, объем библиотеки).
- Обработка версий (`library process`, `trim`, `current`, кадр-обложка) и дата съемки к украшениям не
  применяются — система отвечает `not_for_decoration`. Нужен другой вариант — загрузи новый файл.

## Поиск и карточка

```sh
albumum library list --from 2026-07-01 --to 2026-07-14 --all   # снято в эти дни, все страницы ответа
albumum library list --folder 12 --kind photo                  # каталог, только фото
albumum library list --folder none --unused                    # вне каталогов и ни в одном альбоме
albumum library get 501                                        # карточка: размеры, дата, версии
albumum library used-in 501 502                                # в каких альбомах и листах стоят
albumum library usage                                          # занятый объем и пределы
```

Без `--all` ответ — одна страница с `next_cursor`. Номера файлов (`id`) нужны для верстки листов.

Посмотреть снимок — только по поручению автора (правило 4 скилла `albumum`):
`albumum library image 501 --width 960 -o /tmp/501.webp` (показ-версия не шире `--width`; у видео —
обложка; `no_rendition` — только у еще не готового или не обработанного файла). Показ-версии — WebP:
расширение в `-o` утилита сама приводит к формату (`501.jpg` → `501.webp`, предупреждение в stderr) —
открывай путь из поля `file` ответа. Оригинал — `albumum library original 501 -o ~/Загрузки/501.jpg`,
только если автор просит файл.

## Версии: обработка фото и фрагмент видео

Оригинал не меняется никогда: обработка создает новую версию файла рядом с ним. В карточке
(`albumum library get 501`) версии идут в `versions`, у каждой `id`, `status` (`processing`, `ready`,
`failed`), `is_current`, `operations`. Действующая версия — та, что встает на лист и в библиотеку;
листы, где версия названа явно, не меняются.

```sh
albumum library process 501 --aspect 1:1 --wait           # квадрат по центру, ждать готовности
albumum library process 501 --rotate -1.5 --wait          # выровнять горизонт одним поворотом
albumum library process 501 502 --flip h --rotate 90      # несколько файлов, один рецепт на все
albumum library process 501 --crop 0.1,0.1,0.8,0.8       # рамка долями холста: X,Y,W,H
albumum library trim 610 --start 12.4 --end 52.4 --wait   # фрагмент видео
albumum library current 501 9012                          # сделать версию действующей
albumum library list --derived                            # только файлы с версиями
```

- Порядок операций фиксирован: отражение (`--flip h`, `--flip v`, можно обе), затем поворот
  (`--rotate`, градусы по часовой, −180…180), затем обрезка; порядок флагов в команде значения не имеет.
  Нужна хотя бы одна операция. Рецепт, который ничего не меняет, система отклоняет.
- Обрезка — либо `--aspect Ш:В` (наибольшая рамка этой пропорции по центру: `1:1`, `3:2`, `4:5`), либо
  `--crop X,Y,W,H`; вместе их не задают. Для типового случая «сделать квадрат» или «под пропорции
  листа» бери `--aspect`. После поворота на небольшой угол (выравнивание) система сама обрезает
  пустые углы: одного `--rotate` достаточно.
- Видео: только `trim`; фрагмент не короче 1 с и не длиннее лимита страницы — `page_video_max_seconds`
  из `albumum library usage`. Длиннее — ошибка `too_long` с `limit_s`; на лист такой ролик целиком не
  встанет, сначала нарежь фрагмент.
- Версия готовится в фоне. `--wait` опрашивает карточку раз в 2 с до `ready` или `failed` (не дольше
  300 с). Результат — `items` (`media_id`, `version`, `status`) и `failed` (`media_id`, `error`). Код 6 —
  часть файлов отклонена или не дождалась (`pending: true` — проверь позже `library get`); код 1 — не
  прошел ни один файл. Если пачку оборвали ключ, темп или контракт, в ответе `aborted` (`code`,
  `reason`, `exit_code`) и `not_attempted` — номера файлов, до которых не дошло: исправь причину и
  повтори команду для них. Все версии пачки создаются сразу, `--wait` ждет их вместе; сбой опроса одной
  версии попадает в ее `failed`, остальные не теряются. Файл без оригинала (удален насовсем) —
  `--source ВЕРСИЯ`: от какой версии считать (по умолчанию действующая).
- Файл версии — `albumum library version-file 9012 -o /tmp/v.jpg`, только по просьбе автора.
- Кадр-обложка видеоверсии заранее — `albumum library poster 9012 --at 14.5` (строится один раз; при записи
  листа кадр готовится сам). `poster_busy` (503) — в системе режутся другие кадры: утилита сама ждет
  Retry-After и повторяет до трех раз; если все равно код 1 с `poster_busy` — подожди минуту и повтори.
- Версия в корзину — `albumum library version-trash 9012`: версию в обработке не убрать
  (`not_ready`), у файла должна остаться готовая; версия с ошибкой (`failed`) удаляется сразу
  насовсем. Больше 5 версий за раз или шестое удаление подряд за 10 минут (версии считаются вместе с
  файлами и листами) — предпросмотр (код 2): покажи его человеку дословно, повтор с
  `--confirm ЖЕТОН` только после «да». Вернуть версию — `albumum trash restore version:9012` (она в `trash list`).
- Опубликованный альбом держит свою версию до обновления публикации; новая действующая версия попадет к
  зрителям только после него.

## Каталоги и дата съемки

```sh
albumum library move 501 502 503 --folder 12      # в каталог; --folder none — вне каталогов
albumum library taken-at 501 --at 2026-07-03T09:30          # без смещения — в поясе автора
albumum library taken-at 501 --at 2026-07-03T09:30+05:00    # со смещением — как указано
albumum folders rename 12 "Эльбрус, июль"
albumum folders delete 12                         # файлы остаются в библиотеке, без каталога
```

Дата без смещения — местное время в поясе автора (поле `tz` в `albumum library usage`, например
Europe/Moscow); снимали в другом поясе — передай смещение (`+05:00`, `Z`).

Больше 5 файлов в одной команде `library move`, `library taken-at` и удаление каталога больше чем с
5 файлами требуют подтверждения: код 2 с `preview` — порядок из правила 1 скилла `albumum`.

## Удаление и корзина

```sh
albumum library trash 501 502          # в корзину; стоящие в альбомах станут заглушками «файл в корзине»
albumum trash list                     # в корзине: файлы (media), версии (version), листы (page),
                                       # альбомы (album)
albumum trash restore media:501 page:77
albumum trash purge media:501          # навсегда — всегда с подтверждением
```

- Корзина — без подтверждения до 5 объектов; больше 5 в одном запросе или шестое удаление подряд за
  10 минут — код 2 с `preview` («это N-е удаление подряд»). Не дроби удаление на части, чтобы обойти
  вопрос: покажи человеку весь перечень и спроси один раз.
- Перед удалением файла проверь `albumum library used-in`: стоящий в альбоме файл оставит на листах
  заглушку; опубликованная версия альбома держит свои файлы до следующего обновления публикации.
- `trash purge` необратим: предпросмотр называет, сколько файлов, листов и альбомов уйдет и что
  останется у зрителей. Покажи это человеку дословно и жди явного «да».
- Возврат из корзины подтверждения не требует.
- Украшение уходит в корзину и возвращается, как файл. На листах, где оно стоит, — пометка «украшение в
  корзине» (после окончательного удаления — «украшение удалено»); лист с таким элементом не
  записывается, публикация блокируется, у зрителя опубликованной версии оно остается до обновления.
  Перед удалением — `albumum library used-in 812` и вопрос человеку.
